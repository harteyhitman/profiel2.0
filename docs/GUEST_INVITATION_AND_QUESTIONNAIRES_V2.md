# Guest Invitation & Questionnaires – V2.0

This document describes **how guest invitation and the guest questionnaire flow work**, which **files and code** implement them, and what **setup** is required so V2.0 (or another frontend) can replicate the same behavior.

---

## 1. Overview

There are **two invitation link types** for a **church**:

| Type | Purpose | URL pattern | Result |
|------|--------|-------------|--------|
| **User invitation** | Invite someone to create an account and join the church | `/join-church/:inviteCode` | User registers/logs in → joins church as member |
| **Guest questionnaire** | Invite someone to fill the questionnaire **without an account** | `/questionnaire/guest?inviteCode=:inviteCode` | Guest enters email/name → fills 40 questions → results stored by church invite code + email |

The **guest flow** does **not** require login. The church's **invite code** is the only authorization to access the guest questionnaire and to submit answers. The backend links guest submissions to the church via the invite code.

---

## 2. How guest invitation works

### 2.1 Where the invite code comes from

- Each **church** can have an **invite code** (`inviteCode`).
- It is created/generated by the **backend** when requested by a church admin.
- **Frontend:** Church admins use the **Members** page for a church, where they can:
  - **Generate** an invite code if the church doesn't have one: `POST /api/churches/:id/generate-invite-code`
  - **Copy** one of two links:
    - **User invitation:** `{origin}/join-church/{inviteCode}`
    - **Guest questionnaire:** `{origin}/questionnaire/guest?inviteCode={inviteCode}`

### 2.2 Guest link (what you share)

- **URL:** `https://<your-domain>/questionnaire/guest?inviteCode=<church-invite-code>`
- **Required:** Query parameter `inviteCode` must be present and valid (backend validates it).
- If the user opens `/questionnaire/guest` **without** `inviteCode`, the app shows a "no permission" screen and does not allow filling the questionnaire.

## 3. Guest questionnaire flow (step by step)

1. **User opens link**  
   `GET /questionnaire/guest?inviteCode=xxx`

2. **Permission check (frontend)**  
   - If `inviteCode` is missing → render **NoPermissionToQuestionnaire** (message: ask church leader for a new link, link to homepage, contact).

3. **Step 1 – Collect guest info (no API yet)**  
   - Form: **Email** (required), **First name**, **Last name** (required).
   - Validation: valid email, name min length.
   - On submit: store email, firstName, lastName in component state and set `emailSubmitted = true` → show questionnaire.

4. **Step 2 – Intro (optional)**  
   - Optional intro screen ("Welkom bij de vragenlijst…", how it works, "Start Vragenlijst") then show the 40 questions.

5. **Step 3 – 40 questions**  
   - Same questions as logged-in questionnaire: from **`shared/constants`** → **`QUESTIONS`** (40 items).
   - Each question: two statements (left/right), slider **0–6** (3 = neutral).
   - Responses stored in state as **`QuestionResponse[]`** (see below).
   - Progress: "Vraag X van 40", previous/next, on last question "Volgende" becomes "Afronden".

6. **Step 4 – Submit**  
   - On "Afronden":  
     `POST /api/profile/submit-guest/:inviteCode`  
     **Body:**  
     `{ email, firstName, lastName, responses: QuestionResponse[] }`
   - **Response:** e.g. `{ scores, ... }` (role scores). Frontend can derive primary role from scores.

7. **Step 5 – Completion**  
   - Celebration effect (e.g. confetti), then **GuestCompletionModal**:
     - "Vragenlijst voltooid", results saved for `email`.
     - CTA: "Account aanmaken & Resultaten bekijken" → navigate to `/auth` with state `{ prefillEmail: email }`.
     - "Later afmaken" → navigate to `/`.

## 4. API contract (backend requirements)

### 4.1 Generate church invite code

| Method | Path | Response |
|--------|------|----------|
| POST | `/api/churches/:id/generate-invite-code` | Updated church object including `inviteCode` |

- Backend creates/assigns a unique `inviteCode` for that church and returns the church (e.g. with `inviteCode`).

### 4.2 Submit guest questionnaire

| Method | Path | Body | Response |
|--------|------|------|----------|
| POST | `/api/profile/submit-guest/:inviteCode` | See below | e.g. `{ scores, ... }` |

**Request body:**

```ts
{
  email: string;
  firstName: string;
  lastName: string;
  responses: QuestionResponse[];
}
```

**QuestionResponse (each item):**

```ts
{
  questionId: number;       // 1–40
  value: number;            // 0–6 (3 = neutral)
  statement1Role: string;   // e.g. "apostle", "prophet"
  statement2Role: string;   // e.g. "evangelist", "herder", "teacher"
}
```

- **Roles** must be among: `apostle`, `prophet`, `evangelist`, `herder`, `teacher` (see `src/lib/constants/questionnaire.ts` ROLES).
- Backend should:
  - Validate `inviteCode` (e.g. exists and belongs to a church).
  - Store guest profile + responses linked to the church (and optionally to the email for later account linking).
  - Return at least **scores** (e.g. `apostle`, `prophet`, `evangelist`, `herder`, `teacher`) so the frontend can show primary role in the celebration/completion step.

## 5. Files and code that implement it (this codebase)

### 5.1 Route

- **Guest questionnaire page:**  
  Next.js App Router: `src/app/(main)/questionnaire/guest/page.tsx` → path `/questionnaire/guest`

### 5.2 Pages

| File | Role |
|------|------|
| **`src/app/(main)/questionnaire/guest/page.tsx`** | Main guest flow: read `inviteCode` from query, show NoPermissionToQuestionnaire if missing, email/name form → 40 questions → submit → celebration + GuestCompletionModal. Uses QUESTIONS from `@/lib/constants/questionnaire`, QuestionResponse from `@/lib/api/profile`. |
| **`src/components/dashboard/NoPermissionToQuestionnaire/NoPermissionToQuestionnaire.tsx`** | Shown when `inviteCode` is missing: "Geen toegang tot deze vragenlijst", link to homepage, contact option. |
| **`src/app/(main)/dashboard/members/page.tsx`** | Church members page: opens InvitationLinkModal for user/guest links. |
| **`src/components/dashboard/InvitationLinkModal/InvitationLinkModal.tsx`** | Toggle "Gebruikersuitnodiging" / "Gastuitnodiging", copy user link vs guest link, auto-generate invite code when needed. |

### 5.3 Components

| File | Role |
|------|------|
| **`src/components/dashboard/GuestCompletionModal/GuestCompletionModal.tsx`** | Modal after submit: "Vragenlijst voltooid", results saved for email, CTA to register (same email via prefillEmail) and "Later afmaken". |
| **`src/components/dashboard/CelebrationEffect/CelebrationEffect.tsx`** | Celebration animation after successful submit. |
| **`src/components/dashboard/QuestionCard/QuestionCard.tsx`** | Slider 0–6 for one question (guest page uses it). |

### 5.4 Data and types

| File | Role |
|------|------|
| **`src/lib/constants/questionnaire.ts`** | **QUESTIONS** (40 items), **ROLES**, **TOTAL_QUESTIONS**. |
| **`src/lib/api/profile.ts`** | **QuestionResponse**, **SubmitProfileGuestRequest**, **submitProfileGuest()**. |

### 5.5 Where the guest link is built

- **InvitationLinkModal:**  
  `invitationType === 'guest'` →  
  `${origin}/questionnaire/guest?inviteCode=${inviteCode}`
- **User invitation link:**  
  `invitationType === 'user'` →  
  `${origin}/join-church/${inviteCode}`
